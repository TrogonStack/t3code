# 0044: Dependabot leaves vendored sources alone

- PR: pending
- Status: active

## What you can do now

- Get Dependabot security fixes for the dependencies the app ships, without pull requests that
  bump the vendored reference sources under `.repos/`.

## Why

`.repos/` holds read-only copies of dependency sources for reading, regenerated by
`vpr sync:repos`. A bump there is undone by the next regeneration, after which Dependabot opens it
again, and it can break the copies' own fixtures by mixing versions they never pinned together.

## Upstream considerations

Fork local. Upstream carries no Dependabot configuration, so the file never conflicts on a sync.
